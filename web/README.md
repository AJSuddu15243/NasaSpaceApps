# WEB-1 · Application shell

The shell provides the two public routes (`/` and `/app`), the responsive
three-column workspace, URL-backed scenario state, and the mock engine boundary used
until the Rust/WASM worker is integrated.

## Run

Requires Node 22+ and pnpm 11:

```sh
cd web
pnpm install --frozen-lockfile
pnpm dev
```

Open `http://127.0.0.1:4173/` or `/app`. Every scenario field in the URL is
validated before use. Browser Back and Forward restore the previous scenario.

## Verify

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:browser
```

The browser suite checks desktop and mobile layouts, URL/history behaviour,
keyboard focus, WCAG AA rules, clipboard failure, malformed links, failed requests,
corrupt binary data, retry, and reduced motion.

## What is mocked

Everything in `public/data/mock/` is synthetic and generated by
`scripts/generate-mocks.mjs`. It follows the FND-1 contract shapes but contains no
NASA data. Mock metrics are fixed presentation fixtures; they are available only for
the documented 336 h demo window and never recomputed for a different date or mission
length. Unsupported scenarios show “No computed results” instead of stale numbers.

This PR is stacked on FND-1 PR #65 and imports its generated types and schemas
directly. The engine adapter is isolated in `src/engine/index.ts` so ENG-9 can
replace the mock without changing UI callers.

## Integration boundaries

- WEB-2 is optional at build time. When `src/design/` exists, its stylesheet,
  components, Tailwind preset, and development-only `/design` page are used.
- LND-1 assets remain in their own PR. The shell uses its approved name and copy;
  the favicon/mark can be imported after that PR merges.
- Scene and feature owners mount their work in the labelled centre and side panels.
  The placeholder globe is explicitly illustrative and does not calculate physics.

The app keeps physics out of React and GLSL. Real metrics will come from the
deterministic Rust/WASM worker; scene lighting stays visual only.
